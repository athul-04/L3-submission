# ADR-001: Deterministic Underwriting Decision Service

**Status:** Accepted  
**Scope:** NFR-1 through NFR-8  
**Primary approvers:** Model Risk Committee; Chief Credit Officer

## 1. Context and drivers

Brightmoor Lending requires reproducible first-pass residential underwriting at roughly
40,000 decisions/month. The written policy contains three primary factors, explicit
thresholds, referral rules, an adverse-action gate, and a fair-lending prohibition on
property location as a decision input.

The service must be reproducible to a regulator/applicant, auditable without rerunning,
and below the NFR-4 mean cost ceiling and NFR-5 latency ceiling.

## 2. Determinism (NFR-1)

The **deterministic policy engine is the final authority**. An LLM may be used as a
candidate assessor/verifier, but its output can never change the policy result.

Reproducibility is enforced by:
- exact decimal thresholds encoded in pure Python comparisons;
- no random sampling or model output in the authoritative decision path;
- stable factor evaluation order: credit, DTI, LTV;
- explicit worst-band-wins precedence;
- explicit referral checks before band combination;
- Pydantic validation of every output;
- versioned policy implementation (`deterministic-python-policy-v1`);
- immutable audit records containing the full input and structured output.

Visible threshold cases are APP-5007, APP-5008, APP-5009, APP-5010, APP-5022 and
APP-5023. Each is executed five times and the complete structured decision is compared,
not only the outcome.

### What would break it

A policy code change, changed guideline version, implicit float/rounding transformation,
unordered factor evaluation, non-pinned model version, non-zero sampling temperature,
or allowing an LLM candidate to override the policy authority could break NFR-1.

## 3. Structured output (NFR-2)

`Decision` is a Pydantic model containing outcome, all primary factor values, their
bands, governing provision, reason, approval requirement and issuance state.

A model candidate is parsed into a separate Pydantic candidate schema. Invalid model
output is treated as an invalid candidate and cannot become the authoritative decision;
the deterministic policy result remains the safe fallback.

## 4. Model selection and routing (NFR-6, NFR-4, NFR-5)

The service uses a bounded router:
- `cheap` for straightforward standard-band applications away from boundaries;
- `reasoning` for threshold/boundary cases, adverse-action candidates, enhanced-review
  cases, and referral conditions.

This is a deliberately conservative initial rule. The external benchmark measures
the cheap model's wrong-answer set and the reasoning model's accuracy/latency/cost.
The rule must be revised if observed errors show that a narrower or broader boundary
is justified.

At 40,000 decisions/month, projected cost is calculated from the measured per-route
cost and the observed visible-corpus route mix. No cost figure is fabricated when the
external benchmark has not been run.

## 5. Agentic pattern

The decomposition is intentionally bounded rather than a multi-agent framework:

**Router → Model Boundary/Guard → Model Candidate → Deterministic Verifier → Human Gate**

The router selects verification depth. The boundary controls which fields reach a model.
The deterministic verifier is the authority. The human gate is mandatory for adverse
action. This avoids an autonomous agent being able to create or issue a regulated
decision.

## 6. Governance

The model allowlist contains only:
- credit_score
- debt_to_income
- loan_to_value
- annual_income
- loan_amount
- employment_years

`property_postcode` is excluded because the guidelines explicitly state that property
location is not an underwriting factor and must not influence a decision or any model
that produces one.

`applicant_note` is excluded because it is untrusted intake evidence and has no authority
over the assessment process.

`application_id` is also not sent to the model because it has no policy role.

## 7. Adverse action

A `DECLINE` is prepared with the factor and value responsible, but `issued=False`.
Issuance requires an explicit human reviewer identity and creates a separate audit event.

## 8. Untrusted input

Applicant notes are stored as evidence in the full audit input but are never included
in the model payload and never interpreted as instructions. A note saying "approve
this application" therefore cannot alter the policy result.

## 9. Audit and kill switch

Every decision appends an audit record containing application id, model/route, model
version, full input, model payload, structured output, latency, cost and timestamp.
The runtime kill switch is a file-backed control checked before each decision and can
be changed without redeployment.

## 10. Consequences

### Positive
- Regulated decision logic is reproducible.
- Fair-lending exclusion is structural.
- Model mistakes cannot directly change the final decision.
- Audit records can reconstruct a decision without rerunning it.
- A human remains responsible for adverse action.

### Negative
- Some applications are routed to a more expensive reasoning model.
- Some cases are referred rather than automatically decided.
- The deterministic authority limits the amount of autonomy an LLM can exercise.
- File-backed local audit/kill-switch state is appropriate for the capstone but would
  need a durable transactional store and access control in production.

## 11. Revisit if...

- **Model Risk Committee:** any policy threshold changes or benchmark accuracy drops.
- **Platform Architecture:** p95 latency reaches 1.5 seconds for two consecutive measurement
  runs.
- **Finance/Platform:** projected monthly model cost exceeds $1,500 or mean cost reaches
  $0.04, leaving insufficient headroom below NFR-4.
- **Compliance:** a new prohibited/proxy field is identified.
- **Operations:** an audit reconstruction cannot be completed from the recorded event.

## 12. Alternatives rejected

**LLM as final decision authority:** rejected because stochastic or version-drifting
reasoning conflicts with NFR-1 and makes adverse action unsafe.

**Pure deterministic code with no model measurement:** rejected because NFR-6 explicitly
requires deliberate model selection and measured evidence.

**LangGraph/multi-agent orchestration:** rejected for this capstone because the workflow
is a bounded sequence and additional orchestration state would increase nondeterminism
without improving a required control.
